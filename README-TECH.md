# WT32-ETH01 — RFID/NFC та керування реле

## Призначення

Прошивка для WT32-ETH01 з Ethernet PHY LAN8720 і зчитувачем PN532 через I2C. Пристрій зберігає до 300 карток у LittleFS та вмикає призначене реле на заданий час. Для кожної картки доступні UID, ПІБ, номер автомобіля й дата народження.

RFID і реле працюють автономно: підключення до роутера чи інтернету для зчитування карток не потрібне. Мережа потрібна лише для вебкерування. Якщо Ethernet недоступний, прошивка пробує WiFi збереженої мережі, а за потреби створює власну точку доступу.

## Можливості

- Ethernet через LAN8720 з отриманням IP через DHCP.
- Резервне підключення до WiFi роутера з обліковими даними в EEPROM.
- Локальна WiFi AP `WT32-Config` для налаштування: вона вмикається, якщо Ethernet і збережена WiFi-мережа недоступні; паралельно з робочим Ethernet AP не запускається.
- MQTT-клієнт: публікація подій карток і стану, команди керування реле та списком UID.
- Зчитування UID через PN532 та порівняння зі списком карток у LittleFS.
- Асинхронний HTTP-сервер ESPAsyncWebServer із Fetch/JSON API та WebSocket push.
- Керування двома реле за UID: реле 1, реле 2 або обидва.
- Налаштування тривалості імпульсу та ручне керування реле зі сторінки.
- Додавання UID через вебсторінку або кнопку.
- Повторні спроби ініціалізації PN532, якщо його не знайдено під час запуску.

## Підключення

### PN532 у режимі I2C

| Контакт PN532 | GPIO WT32-ETH01 |
| --- | ---: |
| SDA | 33 |
| SCL | 32 |
| IRQ | 4 |
| RESET | 5 |

У прошивці використано `Adafruit_PN532 nfc(PN532_IRQ, PN532_RESET, &Wire)`.

### Реле та кнопка

| Функція | GPIO |
| --- | ---: |
| Реле 1 | 14 |
| Реле 2 | 15 |
| Кнопка додавання останньої картки | 39 |

Вихід реле в прошивці активується рівнем `HIGH`. Перевірте, що ваш модуль реле сумісний із логікою 3,3 В ESP32.

GPIO39 є лише входом і **не має внутрішньої підтяжки**. Потрібен зовнішній резистор 10 кОм між GPIO39 і 3,3 В; кнопку підключіть між GPIO39 та GND. Без підтяжки вхід може спрацьовувати випадково.

### Ethernet PHY LAN8720

| Параметр | Значення |
| --- | --- |
| PHY | `ETH_PHY_LAN8720` |
| PHY address | `1` |
| Power | GPIO16 |
| MDC | GPIO23 |
| MDIO | GPIO18 |
| Clock | `ETH_CLOCK_GPIO0_IN` |

## Як працює прошивка

### Мережа та автономний режим

Після запуску вебсервер і цикл зчитування карток стартують без очікування на PN532. Прошивка перевіряє Ethernet у фоновому режимі. Якщо протягом 8 секунд Ethernet не отримав IP, вона пробує підключитися до WiFi SSID і пароля з EEPROM протягом 5 секунд. Якщо SSID не збережено або WiFi не підключився, запускається точка доступу.

Якщо під час роботи зникає Ethernet, прошивка використовує вже підключений WiFi STA, якщо він доступний; інакше запускає локальну AP. Якщо зникає WiFi STA, запускається AP. Коли Ethernet знову доступний, він знову стає основним каналом. Втрата мережі не зупиняє зчитування карток і таймери реле.

Підключення до роутера через Ethernet або WiFi потрібне для доступу до сторінки з інших пристроїв у тій самій локальній мережі. Інтернет для RFID-контролю не потрібен.

### Зчитування карток і реле

- PN532 опитується приблизно кожні 400 мс.
- UID нормалізується до великих шістнадцяткових символів із пробілами, наприклад `04 3A 5F 9D`.
- Якщо UID є у списку, відповідне реле вмикається на збережену тривалість.
- Картка, що залишається біля зчитувача, не запускає повторні імпульси. Повторне прикладання тієї самої картки розпізнається після зняття картки.
- Якщо PN532 не відповів під час старту, прошивка повторює спробу приблизно кожні 5 секунд.

Початкова тривалість імпульсу — 1000 мс. Її можна змінити у вебсторінці в межах 50–60000 мс; нове значення зберігається в EEPROM.

Маска реле в записі UID:

| Значення | Дія |
| ---: | --- |
| `1` | Імпульс реле 1 |
| `2` | Імпульс реле 2 |
| `3` | Імпульс обох реле |

Кнопка на GPIO39 додає останній зчитаний UID для реле 1. На вебсторінці можна вибрати реле для додавання останньої картки.

## Вебсторінка

Вебсервер працює на порту 80. Адреса залежить від активного інтерфейсу:

- Ethernet або WiFi роутер: IP, отриманий через DHCP; його прошивка виводить у Serial Monitor.
- Точка доступу `WT32-Config`: `http://192.168.4.1`. Вона запускається як резервний режим, коли Ethernet та збережена WiFi-мережа недоступні; паралельно з робочим Ethernet AP не працює.

Після підключення до `WT32-Config` пристрій перехоплює DNS-запити та перенаправляє HTTP-запити на сторінку входу. Якщо телефон не відкрив вікно автоматично, введіть `http://192.168.4.1` вручну. HTTPS-запити не перенаправляються.

Облікові дані вебсторінки за замовчуванням: `admin` / `ChangeMe123!`.

На сторінці доступні:

- перегляд списку UID та призначених реле;
- додавання UID вручну або підстановку останнього зчитаного UID, а також введення ПІБ, номера авто й дати народження;
- редагування даних уже збережених карток, у тому числі перенесених зі старого списку;
- видалення UID;
- прокручувану таблицю до 300 записів і динамічний пошук за ПІБ/ініціалами, номером авто, датою народження та UID;
- імпульсне керування реле 1, реле 2 або обома та команда вимкнення;
- зміна тривалості імпульсу;
- сторінка `/wifi` для пошуку видимих WiFi мереж, вибору SSID і збереження пароля. Після застосування пристрій одразу пробує підключитися до вибраної мережі, якщо Ethernet недоступний; при підключеному Ethernet він лишається основним.

Стан і події зчитування передаються WebSocket приблизно щосекунди. Якщо
WebSocket недоступний, сторінка повторно запитує стан кожні 10 секунд,
активність — кожні 15 секунд, а список карток — кожні 10 секунд.

### MQTT

MQTT вимкнений, доки не задано адресу брокера. Налаштуйте брокер на сторінці `/mqtt` через вебінтерфейс: вкажіть IP/ім’я Raspberry Pi, порт (типово `1883`), необов’язкові логін і пароль та базовий topic (типово `wt32/controller`). Налаштування зберігаються в EEPROM. Порожнє поле пароля залишає збережений пароль. Після збереження WT32 автоматично повторює підключення кожні 5 секунд.

Клієнт використовує Ethernet, коли він має IP, або резервний WiFi STA. У режимі AP без підключення до роутера брокер недоступний, але локальна вебсторінка залишається доступною. MQTT використовує незашифрований TCP; запускайте брокер лише у довіреній локальній мережі та налаштуйте на ньому пароль.

Для базового топіка `wt32/controller`:

| Topic | Напрямок | Payload |
| --- | --- | --- |
| `wt32/controller/status` | WT32 → брокер | Retained JSON: `online`, `network`, `ip`, `pn532`, `relay1`, `relay2` |
| `wt32/controller/event/card` | WT32 → брокер | JSON: `uid`, `authorized`, `relay` для нової картки |
| `wt32/controller/cmd/relay` | брокер → WT32 | JSON-команда реле |
| `wt32/controller/cmd/card/add` | брокер → WT32 | JSON з `uid` і `relay` (1–3) |
| `wt32/controller/cmd/card/remove` | брокер → WT32 | JSON з `uid`; видаляє всі записи цього UID |
| `wt32/controller/result` | WT32 → брокер | Підтвердження команди: `command`, `ok` |

Приклади повідомлень:

```json
{"action":"pulse","mask":1,"duration":1000}
{"action":"stop","mask":1}
{"uid":"04 3A 5F 9D","relay":1}
{"uid":"04 3A 5F 9D"}
```

Для команди реле `mask`: `1` — реле 1, `2` — реле 2, `3` — обидва. `duration` у команді `pulse` необов’язковий; якщо його не передати, береться збережена тривалість імпульсу. Новий UID має бути у форматі HEX-байтів через пробіл; UID перевіряється так само, як у вебінтерфейсі.

#### Приклад брокера Mosquitto на Raspberry Pi

Встановіть брокер:

```bash
sudo apt update
sudo apt install mosquitto mosquitto-clients
sudo systemctl enable --now mosquitto
```

Створіть пароль для пристрою:

```bash
sudo mosquitto_passwd -c /etc/mosquitto/passwd wt32
```

Додайте конфігурацію віддаленого доступу, наприклад у `/etc/mosquitto/conf.d/lan.conf`:

```text
listener 1883
allow_anonymous false
password_file /etc/mosquitto/passwd
```

Після цього перезапустіть брокер командою `sudo systemctl restart mosquitto`. У `/mqtt` вкажіть локальну IP-адресу Raspberry Pi, порт `1883`, логін `wt32` і створений пароль. Закріпіть IP Raspberry Pi в DHCP налаштуваннях роутера, щоб адреса брокера не змінювалася.

### HTTP API

Усі маршрути вимагають HTTP Basic Authentication.

| Маршрут | Метод | Призначення |
| --- | --- | --- |
| `/` | GET | Вебінтерфейс |
| `/api/list` | GET | Список карток у JSON: UID, ПІБ, номер авто, дата народження та реле |
| `/api/search-log` | POST | Діагностика пошуку: записати в Serial Monitor запит і кількість знайдених інтерфейсом карток |
| `/api/activity` | GET | Останні десять зчитаних UID, статистика частоти й журнали прибуття/вибуття |
| `/api/attendance` | POST | Додати позначку прибуття або вибуття (`uid`, `action=arrive|depart`) |
| `/api/status` | GET | Останній UID, стан PN532 і мережі |
| `/api/mqtt-config` | GET | Поточні MQTT-параметри без пароля |
| `/api/add` | POST | Додати картку (`uid`, `relay`, необов’язкові `lastName`, `firstName`, `middleName`, `vehicle`, `birthDate`) |
| `/api/update` | POST | Оновити поля картки за `index` |
| `/api/add-last` | POST | Додати останній зчитаний UID (`relay`) |
| `/api/remove` | POST | Видалити запис (`index`) |
| `/api/relay` | POST | Керування реле (`action`, `mask`, за потреби `duration`) |
| `/api/settings` | POST | Зберегти тривалість (`duration`) |
| `/wifi` | GET/POST | Пошук мереж, вибір SSID і збереження WiFi налаштувань |
| `/wifi/scan` | GET | Асинхронне сканування видимих WiFi мереж |
| `/mqtt` | GET/POST | Перегляд і збереження MQTT налаштувань |
| `/ws` | WebSocket | Push стану пристрою щосекунди й UID після зчитування |
| `/style.css`, `/app.js`, `/wifi.js`, `/mqtt.js` | GET | Статичні web-assets із LittleFS |

Fetch API надсилає POST-запити як `application/json`, відповіді API мають формат
JSON. Картки, налаштування WiFi та MQTT редагуються без перезавантаження
сторінки; WebSocket передає стан і нові зчитування.

Для `/api/relay` використовуйте `action=pulse` для імпульсу або `action=stop` для вимкнення. `mask` дорівнює 1, 2 або 3. Тривалість імпульсу в запиті можна передати окремо; якщо її не передано, використовується збережене значення.

На сторінці `/wifi` виберіть знайдену мережу або введіть SSID вручну. Для тієї самої мережі порожнє поле пароля залишає поточний пароль; для нової мережі порожній пароль налаштовує підключення до відкритої мережі. Після застосування налаштування зберігаються й пристрій автоматично починає підключення, не потребуючи перезавантаження. Ethernet залишається основним, якщо він має IP-адресу; без Ethernet використовується збережений WiFi, а при невдалому підключенні запускається точка доступу налаштування.

## Зберігання карток та налаштувань

HTML/CSS/JS-файли вебінтерфейсу розміщені в розділі LittleFS `littlefs`; дані карток та журнал прибуття/вибуття — в окремому LittleFS-розділі `cardfs`. Це дозволяє оновлювати web-assets командою `platformio run --target uploadfs`, не стираючи реєстр. Під час першого запуску прошивка намагається скопіювати файли `/cards.jsonl` та `/attendance.jsonl` зі старого розділу SPIFFS; сам старий розділ не змінюється. Міграція вдається лише тоді, коли старий SPIFFS монтується у збереженому розташуванні. Якщо Serial Monitor повідомляє, що старий SPIFFS недоступний, ці файли не перенесено. Коли `/cards.jsonl` немає в новому сховищі, прошивка також намагається перенести UID із 30 старих EEPROM-слотів. Перезапис даних у `cardfs` використовує тимчасові та резервні файли.

Для кожної картки `/cards.jsonl` також зберігає лічильник зчитувань (до 65 535) і час останнього зчитування Unix (UTC) з точністю до хвилини. Зміни статистики записуються пакетно не частіше ніж раз на хвилину активного зчитування. `/attendance.jsonl` зберігає останні 10 подій прибуття та 10 подій вибуття.

Таблиця розділів зберігає старий SPIFFS у незміненій адресі, займає колишній OTA slot для web-assets і окремо відводить LittleFS для даних. OTA-прошивання не підтримується з цією таблицею; оновлення прошивки відбувається через USB/serial. Команда `uploadfs` оновлює лише web-assets розділу `littlefs`.

Час синхронізується SNTP/NTP (`pool.ntp.org`, `time.google.com`) і налаштований для Europe/Kyiv з урахуванням літнього часу. Якщо час ще не синхронізовано, журнальні події все одно зберігаються з нульовою міткою часу, а вебсторінка показує стан очікування синхронізації.

WiFi, тривалість імпульсу та MQTT-параметри лишаються в EEPROM:

| Дані | Адреса / параметр |
| --- | ---: |
| Старий список для одноразового перенесення | `0`–`959` |
| WiFi SSID | `1000` |
| WiFi пароль | `1040` |
| Тривалість імпульсу | `1104` |
| MQTT host | `1120` |
| MQTT port | `1186` |
| MQTT user | `1190` |
| MQTT password | `1224` |
| MQTT base topic | `1290` |
| Маркер старого сховища карток | `1400` |
| Маркер LittleFS data partition | `1401` |
| Розмір EEPROM | `2048` байтів |

Персональні дані зберігаються без шифрування у файловій системі та передаються вебінтерфейсом через HTTP без TLS. Використовуйте пристрій лише у довіреній локальній мережі, змініть стандартний пароль вебінтерфейсу та не відкривайте його безпосередньо в інтернет.

Для діагностики додавання й редагування Serial Monitor виводить UID та всі введені персональні поля. Діагностика пошуку виводить пошуковий запит і кількість збігів, яку показав вебінтерфейс. Ці повідомлення можуть містити персональні дані; захищайте доступ до Serial Monitor.

## Налаштування та безпека

Поточні облікові дані точки доступу: `WT32-Config` / `config1234`. AP запускається, якщо Ethernet не отримав IP, а збережена WiFi-мережа не підключилася; при робочому Ethernet AP вимкнена. Вебсторінка також захищена HTTP Basic Authentication. Перед використанням у спільній мережі змініть `webUser`, `webPass` і пароль AP у `src/main.cpp`.

Якщо Serial Monitor часто повідомляє `Немає останнього UID для додавання`, перевірте кнопку на GPIO39: цьому входу потрібен зовнішній резистор 10 кОм до 3,3 В, а кнопка підключається до GND. Код має 50 мс антидребезгу та обмежує повтор повідомлення.

Повідомлення `PN532 не знайдено` стосується зчитувача, а не вебсервера. Перевірте, що модуль встановлено в режим I2C, SDA підключено до GPIO33, SCL до GPIO32, а живлення та GND спільні з WT32-ETH01. Прошивка продовжує повторні спроби й обмежує діагностичне повідомлення одним разом на 30 секунд.

Вебінтерфейс використовує звичайний HTTP, а не HTTPS. Підключайтеся до нього лише в довіреній локальній мережі.

## Збірка та прошивання

У `platformio.ini` виберіть правильний COM-порт у `upload_port` і `monitor_port`. Команди з кореня проєкту:

```bash
python -m platformio run
python -m platformio run --target upload
python -m platformio device monitor
```

Щоб переглянути доступні порти:

```bash
python -m platformio device list
```

Для першого переходу на нову таблицю розділів прошийте firmware через USB/serial, потім окремо завантажте web-assets командою `uploadfs`. Прошивка не форматує старий SPIFFS і лише намагається скопіювати його дані до LittleFS `cardfs`; перевірте повідомлення про результат у Serial Monitor. Не використовуйте стару OTA-схему: OTA slot тепер зайнятий файловою системою.
   
Після прошивання перевірте Serial Monitor: там з’являються стан PN532, адреса вебсторінки та результати зчитування UID.
