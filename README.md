# WT32-ETH01 NFC + Relay Controller

Проект для WT32-ETH01 на базі ESP32. Основна ідея — зчитувати UID карток через PN532, знаходити їх у списку дозволених карток і вмикати призначене реле.

## Що має проект

- Ethernet як основний канал зв'язку
- WiFi як резервний варіант (STA або AP)
- автоматична captive-сторінка налаштування при підключенні до AP та email-повідомлення про зміну мережі/IP через Gmail SMTP
- MQTT для передачі подій і віддалених команд
- два PN532: перший через I2C, другий через SPI
- зберігання до 300 карток у LittleFS з UID, ПІБ, номером авто, датою народження, адресою, телефоном та призначеним реле
- асинхронний вебсервер ESPAsyncWebServer, окремі HTML/CSS/JS-файли в LittleFS, Fetch API з JSON і WebSocket push для стану та нових UID
- веб-інтерфейс із прокручуваною таблицею; пошук за прізвищем/ініціалами, номером авто, датою народження, адресою, телефоном або UID працює під час введення, через Enter чи кнопку «Знайти», а картки можна змінювати та видаляти кнопками у рядках таблиці
- спільний облік присутності в оперативній пам’яті: PN532 №1 та MQTT-команда `arrive` додають зареєстровану картку, PN532 №2 та MQTT-команда `depart` прибирають її; панель «Присутні зараз» оновлюється через WebSocket і контрольний запит кожні 5 секунд. Вебсторінка дозволяє вибрати картку в результатах пошуку або присутні номерні рамки й позначити прибуття/вибуття біля поля пошуку. Поточний список скидається після перезавантаження
- щонайменше шість номерних рамок для присутніх авто; код країни (UA, PL, DE, GB, FR, IT або ES) та окремих штатів США визначається за впізнаваними масками номера. Для польського номера потрібен видимий пробіл між літерами та цифрами; для збігу FL/CO у форматі 4 літери + 2 цифри літера A–N віддає перевагу FL, а O–Z — CO. Для інших перекривних масок застосовується пріоритет специфічнішого шаблону; числові й нерозрізнювані формати не позначаються. Це евристика за текстом номера, а не гарантована географічна перевірка
- автоматична captive-сторінка для точки доступу; таблиця карток із прокручуванням і висотою до 10 рядків; налаштовувані Gmail-повідомлення про IP при зміні активної мережі Ethernet/WiFi
- годинник, синхронізований через NTP і відображений за київським часом
- MQTT через брокер у локальній мережі: статус, UID, реле та зміни списку карток
- кнопку для додавання останнього відсканованого UID
- керування двома реле
- спільна черга імпульсів для NFC, MQTT та вебсторінки; вимкнення має окремий пріоритетний буфер, а таймер реле працює у FreeRTOS-задачі незалежно від мережевих операцій

## Підключення PN532 NFC Module V3

Використовуються два червоні модулі PN532 NFC Module V3. Перший модуль
налаштуйте перемикачами в режим I2C, другий — у режим SPI.

**PN532 №1 — I2C**

- SDA → GPIO 33
- SCL → GPIO 32
- IRQ → GPIO 36
- RESET / RSTO → GPIO 5
- VCC → 3,3 V; GND → GND

**PN532 №2 — SPI**

- SCK → GPIO 17
- MOSI → GPIO 13
- MISO → GPIO 35
- SS / NSS / CS → GPIO 4
- VCC → 3,3 V; GND → GND

У режимі SPI IRQ та RESET другого модуля до плати не під’єднуються. GPIO4
зарезервований як CS другого модуля, тому IRQ першого під’єднайте до GPIO36.
З’єднайте GND обох модулів із GND плати та не подавайте 5 В на GPIO ESP32.

## Інші піни

- RELAY_1: GPIO 14
- RELAY_2: GPIO 15
- BUTTON_ADD: GPIO 39 — потрібен зовнішній резистор 10 кОм до 3.3 V; кнопку підключити між GPIO39 та GND

## Швидкий опис логіки

- Після запуску пристрій пробує підняти Ethernet.
- Ethernet отримує IP-адресу від роутера через DHCP.
- Резервний WiFi використовує збережені в EEPROM облікові дані або значення `WIFI_DEFAULT_SSID` / `WIFI_DEFAULT_PASSWORD` із `src/main.cpp`; збережені через `/wifi` дані мають пріоритет.
- Якщо Ethernet недоступний, пристрій робить до трьох спроб підключення до збереженого WiFi (до 20 секунд кожна), а потім запускає AP `WT32-Config`; після невдалого циклу спроб він очікує хвилину й пробує знову.
- Коли Ethernet або WiFi роутера доступний, відкрийте адресу, яку пристрій вивів у Serial Monitor або отримайте її листом після налаштування email. AP не запускається паралельно з робочим Ethernet.
- Відсутність PN532 не блокує старт вебсервера: прошивка продовжує повторні спроби ініціалізації зчитувача.
- Після сканування картки система отримує UID і шукає його у списку карток у LittleFS.
- Якщо UID знайдений, активується відповідне реле.
- PN532 №1 позначає картку присутньою, PN532 №2 — відсутньою; повторне вибуття не є помилкою. Обидва зчитувачі однаково перевіряють UID і запускають призначене реле.
- MQTT-команди прибуття та вибуття змінюють той самий стан присутності, що й PN532. Для `arrive`/`depart` передайте `uid` або зареєстрований `vehicle` у команді `cmd/presence`; невідомі UID і номери авто відхиляються. Зміна надсилається як MQTT-подія `event/presence`, а вебсторінка оновлює список без перезавантаження.
- Через веб-сторінку можна переглядати список, додавати нові UID і видаляти існуючі записи.

## Перевірка MQTT з Ubuntu 24.04

Встановіть клієнти Mosquitto, задайте адресу брокера й увійдіть у пароль прихованим вводом:

```bash
sudo apt update
sudo apt install -y mosquitto-clients
BROKER=192.168.1.50
MQTT_USER=wt32
MQTT_BASE=wt32/controller
read -rsp 'Пароль MQTT: ' MQTT_PASS; echo
mqtt_pub() {
  mosquitto_pub -h "$BROKER" -p 1883 -u "$MQTT_USER" -P "$MQTT_PASS" \
    -t "$MQTT_BASE/$1" -m "$2"
}
```

Замініть `192.168.1.50` і за потреби ім’я користувача на свої значення. У першому терміналі запустіть підписку, щоб бачити події карток, відповіді та підтвердження команд:

```bash
mosquitto_sub -h "$BROKER" -p 1883 -u "$MQTT_USER" -P "$MQTT_PASS" \
  -t "$MQTT_BASE/event/card" \
  -t "$MQTT_BASE/data/card/latest" \
  -t "$MQTT_BASE/result" -v
```

В іншому терміналі задайте ті самі `BROKER`, `MQTT_USER`, `MQTT_BASE`, введіть пароль і створіть функцію `mqtt_pub` (встановлювати пакет повторно не потрібно), тоді надсилайте команди:

```bash
# Тимчасові імпульси по 1 секунді
mqtt_pub cmd/relay '{"action":"pulse","mask":1,"duration":1000}'
mqtt_pub cmd/relay '{"action":"pulse","mask":2,"duration":1000}'

# Постійне ввімкнення: залишається до off/stop або перезапуску пристрою
mqtt_pub cmd/relay '{"action":"on","mask":1}'
mqtt_pub cmd/relay '{"action":"on","mask":2}'

# Вимкнення
mqtt_pub cmd/relay '{"action":"off","mask":1}'
mqtt_pub cmd/relay '{"action":"off","mask":2}'
```

`mask: 1` — реле 1, `mask: 2` — реле 2, `mask: 3` — обидва. `pulse` приймає тривалість 50–60000 мс; без `duration` використовується збережене значення. `on` не має таймера — перед тестом переконайтеся, що постійне ввімкнення безпечне для підключеного обладнання.

Коли картку піднесено до зчитувача, її UID надходить у `event/card`. Щоб отримати останній зчитаний UID окремим запитом, спершу залиште активною підписку вище, а тоді виконайте:

```bash
mqtt_pub cmd/card/latest '{"requestId":"ubuntu-check-1"}'
```

Відповідь з’явиться в `data/card/latest`; якщо після запуску картку ще не зчитували, поле `found` буде `false`. Деталі форматів і всіх MQTT-команд наведені в [README-TECH.md](./README-TECH.md#MQTT).

## Дані картки

Для кожної картки зберігаються UID, прізвище, ім’я, по батькові, номер автомобіля, дата народження, адреса, телефон та режим реле. Особисті поля можна залишити порожніми; UID та реле потрібні для роботи контролю доступу. Старі записи карток без адреси та телефону завантажуються з порожніми контактними полями.

## Веб-інтерфейс

Після запуску пристрій відкриває веб-сервер на порту 80.
Якщо пристрій підключився до Ethernet або WiFi роутера, відкрийте IP-адресу,
яку він показав у Serial Monitor або яку видно в списку DHCP-клієнтів роутера.
Якщо мережа роутера недоступна, підключіться до AP `WT32-Config`
(пароль `config1234`). Телефон або комп’ютер зазвичай показує captive-вікно
з кнопкою «Відкрити налаштування WiFi»; якщо цього не сталося, відкрийте
`http://192.168.4.1` вручну. Автоматичний виклик captive-вікна залежить від ОС
і не може бути гарантований самим пристроєм.
AP запускається лише як резервний режим, а не паралельно з робочим Ethernet.
Вебсторінка захищена HTTP Basic Authentication: браузер попросить ім’я та пароль.

- / — головна сторінка
- /api/list — список UID
- /api/search-log — журнал пошукового запиту та кількості збігів у Serial Monitor
- /api/activity — сумісний API історії зчитувань і прибуттів/вибуттів; вебсторінка його не викликає
- /api/attendance — позначення прибуття або вибуття (`uid`, `action=arrive|depart`)
- /api/presence — зареєстровані картки з поточним станом присутності
- /api/status — стан пристрою
- /api/mqtt-config — поточні MQTT-параметри без пароля
- /api/add — додавання UID
- /api/update — редагування даних збереженої картки
- /api/add-last — додавання останнього зчитаного UID
- /api/remove — видалення UID
- /api/relay — керування реле
- /api/settings — налаштування тривалості імпульсу
- /wifi — налаштування WiFi
- /wifi/scan — пошук видимих WiFi-мереж
- /mqtt — налаштування MQTT-брокера

Сторінки, API та WebSocket `/ws` потребують HTTP Basic Authentication.
Fetch API надсилає POST-дані як JSON; WebSocket передає стан приблизно раз
на секунду та нові події зчитування й присутності. Клієнт також запитує
`/api/presence` кожні 5 секунд як резервну синхронізацію; за паралельних
відповідей застосовується лише найновіший результат.

У головному вебінтерфейсі список має власну область прокручування. Пошук
оновлюється під час введення й працює за ПІБ (у тому числі ініціалами),
номером авто, датою народження та UID. Максимум — 300 карток.
Кнопка «Редагувати» дає змогу доповнити персональні дані вже наявних карток,
зокрема UID, автоматично перенесених зі старого списку. Панель «Присутні зараз»
показує зареєстровані присутні картки; вибір плитки лише додає її до списку
вибраних, не змінюючи стану присутності. Вибір обмежений десятьма записами.

На сторінці `/wifi` натисніть «Знайти WiFi мережі», виберіть потрібну зі списку,
введіть пароль і натисніть «Зберегти та підключити», щоб записати параметри.
Якщо Ethernet підключений, він залишається основним; якщо Ethernet недоступний,
пристрій пробує підключитися до вибраного WiFi. Якщо підключення не вдається,
пристрій запускає точку доступу налаштування.

Під час першого запуску прошивка намагається скопіювати файли карток і журналу
зі старого розділу SPIFFS у окремий розділ LittleFS; старий розділ не змінюється.
Міграція можлива, лише якщо старий SPIFFS доступний у збереженому розташуванні.
Якщо в Serial Monitor з’явиться повідомлення, що старий SPIFFS недоступний,
ці файли не перенесено. Якщо файлу карток немає в новому сховищі, прошивка
також намагається перенести до 30 UID зі старих EEPROM-слотів; самі слоти
не очищаються. Новий список підтримує до 300 карток із ПІБ, номером авто
та датою народження.
Лічильник зчитувань та час останнього зчитування зберігаються разом із карткою
у LittleFS; статистика записується пакетно приблизно раз на хвилину, лічильник
зберігається до 65 535 зчитувань, а час останнього зчитування має точність до
хвилини. Журнал прибуття/вибуття переживає перезавантаження й зберігає до
10 записів кожного типу. Час пристрою синхронізується через NTP; у браузері
відображається Europe/Kyiv.

Сторінки зберігаються в `data/` та завантажуються окремою командою
`platformio run --target uploadfs`. Сховище карток розміщене в іншому розділі,
тому оновлення web-файлів не стирає картки. Нова таблиця розділів використовує
раніше зарезервований OTA slot для LittleFS та вимикає OTA-оновлення прошивки.

MQTT вимкнений, доки не вказано брокер. На сторінці `/mqtt` задайте IP-адресу
Raspberry Pi, порт (типово `1883`), логін/пароль за наявності та базовий topic
(типово `wt32/controller`). Клієнт надсилає статус і події карток та присутності, приймає
JSON-команди реле, додавання/видалення UID і прибуття/вибуття за UID або
номером авто. За MQTT-командою можна запитати списки карток, присутніх та
відсутніх. MQTT-прибуття/вибуття оновлює спільний RAM-список присутності й
відображається в панелі вебсторінки; стан списку не переживає перезавантаження,
хоча журнал подій прибуття/вибуття зберігається. Ethernet використовується як
основний транспорт, збережена WiFi-мережа — як резервний; коли доступна лише
локальна AP без зв’язку з роутером, MQTT-брокер недоступний.

Для прикладів MQTT payload, команд і встановлення Mosquitto на Raspberry Pi
дивіться [README-TECH.md](./README-TECH.md#MQTT).

## Як прошити плату

### Підключення

- ESP32 програмний порт (USB-UART) підключається до UART плати WT32-ETH01
- Підтвердіть, який COM-порт реально використовується в Device Manager
- Для прошивки в PlatformIO зазвичай використовується порт, який відповідає `upload_port = COMx`

### Команди PlatformIO у терміналі Windows

Відкрийте термінал VS Code (**Terminal → New Terminal**) і перейдіть у папку
проєкту. Підключіть плату через USB-UART та дочекайтеся завершення кожної
команди перед запуском наступної:

```powershell
cd "$env:USERPROFILE\Documents\PlatformIO\Projects\wt32-eth01"
.\.venv\Scripts\platformio.exe run --target upload
.\.venv\Scripts\platformio.exe run --target uploadfs
```

Спочатку виконайте `upload`, потім — `uploadfs`: друга команда завантажує
вебсторінки в LittleFS. Не стирайте Flash. Розділ карток відокремлений, тому
`uploadfs` не повинен видаляти збережені картки.

### Якщо потрібна перевірка серійного порту

```bash
python -m platformio device list
```

### Підсумок підключень

- PN532 NFC Module V3 №1 у режимі I2C: SDA -> GPIO 33, SCL -> GPIO 32,
  IRQ -> GPIO 36, RESET/RSTO -> GPIO 5, VCC -> 3,3 V, GND -> GND
- PN532 NFC Module V3 №2 у режимі SPI: SCK -> GPIO 17, MOSI -> GPIO 13,
  MISO -> GPIO 35, SS/NSS/CS -> GPIO 4, VCC -> 3,3 V, GND -> GND
- RELAY_1 -> GPIO 14
- RELAY_2 -> GPIO 15
- BUTTON_ADD -> GPIO 39
- Ethernet PHY LAN8720 -> як у конфігурації ETH

Встановіть перемикачі кожного модуля відповідно до його режиму. IRQ та RESET
модуля №2 у цій SPI-схемі не підключаються. GPIO35 є лише входом: використовуйте
його для MISO, не для SCK/MOSI. Не подавайте 5 В на GPIO ESP32.

## Примітка

Якщо сторінка відкрита через роутер, використовуйте DHCP-адресу WT32-ETH01,
а не `192.168.4.1` (це адреса резервної точки доступу). Перевірте фактичні
пін-назначення вашої плати перед підключенням периферії.
