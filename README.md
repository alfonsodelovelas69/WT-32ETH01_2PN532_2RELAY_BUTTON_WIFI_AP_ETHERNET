# WT32-ETH01 NFC + Relay Controller

Проект для WT32-ETH01 на базі ESP32. Основна ідея — зчитувати UID карток через PN532, знаходити їх у списку дозволених карток і вмикати призначене реле.

## Що має проект

- Ethernet як основний канал зв'язку
- WiFi як резервний варіант (STA або AP)
- MQTT для передачі подій і віддалених команд
- PN532 через I2C
- зберігання до 300 карток у LittleFS з UID, ПІБ, номером авто, датою народження та призначеним реле
- асинхронний вебсервер ESPAsyncWebServer, окремі HTML/CSS/JS-файли в LittleFS, Fetch API з JSON і WebSocket push для стану та нових UID
- веб-інтерфейс із прокручуваною таблицею; пошук за прізвищем/ініціалами, номером авто, датою народження або UID працює під час введення, через Enter чи кнопку «Знайти», а картки можна змінювати та видаляти кнопками у рядках таблиці
- список десяти останніх зчитаних карток, ручні позначки прибуття/вибуття та перегляд останніх десяти записів кожного типу
- статистика десяти найдавніше не зчитуваних і десяти найчастіше зчитуваних карток; годинник синхронізується через NTP та відображається за київським часом
- MQTT через брокер у локальній мережі: статус, UID, реле та зміни списку карток
- кнопку для додавання останнього відсканованого UID
- керування двома реле

## Піни

- PN532 SDA: GPIO 33
- PN532 SCL: GPIO 32
- PN532 IRQ: GPIO 4
- PN532 RESET: GPIO 5
- RELAY_1: GPIO 14
- RELAY_2: GPIO 15
- BUTTON_ADD: GPIO 39 — потрібен зовнішній резистор 10 кОм до 3.3 V; кнопку підключити між GPIO39 та GND

## Швидкий опис логіки

- Після запуску пристрій пробує підняти Ethernet.
- Ethernet отримує IP-адресу від роутера через DHCP.
- Якщо Ethernet не підключився або DHCP не видав IP, пристрій намагається підключитися до WiFi зі збережених даних.
- Якщо WiFi SSID не збережений або WiFi не підключився, запускається AP `WT32-Config`.
- Коли Ethernet або WiFi роутера доступний, відкрийте адресу, яку пристрій вивів у Serial Monitor. AP не запускається паралельно з робочим Ethernet.
- Відсутність PN532 не блокує старт вебсервера: прошивка продовжує повторні спроби ініціалізації зчитувача.
- Після сканування картки система отримує UID і шукає його у списку карток у LittleFS.
- Якщо UID знайдений, активується відповідне реле.
- Через веб-сторінку можна переглядати список, додавати нові UID і видаляти існуючі записи.

## Дані картки

Для кожної картки зберігаються UID, прізвище, ім’я, по батькові, номер автомобіля, дата народження та режим реле. Особисті поля можна залишити порожніми; UID та реле потрібні для роботи контролю доступу.

## Веб-інтерфейс

Після запуску пристрій відкриває веб-сервер на порту 80.
Якщо пристрій підключився до Ethernet або WiFi роутера, відкрийте IP-адресу,
яку він показав у Serial Monitor або яку видно в списку DHCP-клієнтів роутера.
Якщо мережа роутера недоступна, підключіться до AP `WT32-Config`
(пароль `config1234`) та відкрийте `http://192.168.4.1`.
AP запускається лише як резервний режим, а не паралельно з робочим Ethernet.
Вебсторінка захищена HTTP Basic Authentication: браузер попросить ім’я та пароль.

Основні маршрути:
- / — головна сторінка
- /api/list — список UID
- /api/search-log — журнал пошукового запиту та кількості збігів у Serial Monitor
- /api/activity — останні зчитування, лічильники та журнали прибуття/вибуття
- /api/attendance — позначення прибуття або вибуття (`uid`, `action=arrive|depart`)
- /api/status — стан пристрою
- /api/mqtt-config — поточні MQTT-параметри без пароля
- /api/add — додавання UID
- /api/update — редагування даних збереженої картки
- /api/add-last — додавання останнього зчитаного UID
- /api/remove — видалення UID
- /api/relay — керування реле
- /api/settings — налаштування тривалості імпульсу
- /wifi — налаштування WiFi
- /wifi/scan — пошук видимих WiFi-мереж
- /mqtt — налаштування MQTT-брокера

Сторінки, API та WebSocket `/ws` потребують HTTP Basic Authentication.
Fetch API надсилає POST-дані як JSON; WebSocket передає стан приблизно раз
на секунду та нові події зчитування.

У головному вебінтерфейсі список має власну область прокручування. Пошук
оновлюється під час введення й працює за ПІБ (у тому числі ініціалами),
номером авто, датою народження та UID. Максимум — 300 карток.
Кнопка «Редагувати» дає змогу доповнити персональні дані вже наявних карток,
зокрема UID, автоматично перенесених зі старого списку.

На сторінці `/wifi` натисніть «Знайти WiFi мережі», виберіть потрібну зі списку,
введіть пароль і натисніть «Зберегти та підключити», щоб записати параметри.
Якщо Ethernet підключений, він залишається основним; якщо Ethernet недоступний,
пристрій пробує підключитися до вибраного WiFi. Якщо підключення не вдається,
пристрій запускає точку доступу налаштування.

Під час першого запуску прошивка намагається скопіювати файли карток і журналу
зі старого розділу SPIFFS у окремий розділ LittleFS; старий розділ не змінюється.
Міграція можлива, лише якщо старий SPIFFS доступний у збереженому розташуванні.
Якщо в Serial Monitor з’явиться повідомлення, що старий SPIFFS недоступний,
ці файли не перенесено. Якщо файлу карток немає в новому сховищі, прошивка
також намагається перенести до 30 UID зі старих EEPROM-слотів; самі слоти
не очищаються. Новий список підтримує до 300 карток із ПІБ, номером авто
та датою народження.
Лічильник зчитувань та час останнього зчитування зберігаються разом із карткою
у LittleFS; статистика записується пакетно приблизно раз на хвилину, лічильник
зберігається до 65 535 зчитувань, а час останнього зчитування має точність до
хвилини. Журнал прибуття/вибуття переживає перезавантаження й зберігає до
10 записів кожного типу. Час пристрою синхронізується через NTP; у браузері
відображається Europe/Kyiv.

Сторінки зберігаються в `data/` та завантажуються окремою командою
`platformio run --target uploadfs`. Сховище карток розміщене в іншому розділі,
тому оновлення web-файлів не стирає картки. Нова таблиця розділів використовує
раніше зарезервований OTA slot для LittleFS та вимикає OTA-оновлення прошивки.

MQTT вимкнений, доки не вказано брокер. На сторінці `/mqtt` задайте IP-адресу
Raspberry Pi, порт (типово `1883`), логін/пароль за наявності та базовий topic
(типово `wt32/controller`). Клієнт надсилає статус і події карток та приймає
JSON-команди реле й додавання/видалення UID. Ethernet використовується як
основний транспорт, збережена WiFi-мережа — як резервний; коли доступна лише
локальна AP без зв’язку з роутером, MQTT-брокер недоступний.

Для прикладів MQTT payload, команд і встановлення Mosquitto на Raspberry Pi
дивіться [README-TECH.md](./README-TECH.md#MQTT).

## Безпека

За замовчуванням логін і пароль для веб-інтерфейсу:

- логін: admin
- пароль: ChangeMe123!

Перед реальним використанням змініть їх у `src/main.cpp` і перепрошийте
пристрій. Вебінтерфейс використовує HTTP без шифрування, тому користуйтеся ним
лише у довіреній локальній мережі. ПІБ, номери авто й дати народження також
зберігаються без шифрування; не відкривайте пристрій безпосередньо в інтернет.

## Будівництво

Проект збирається через PlatformIO з конфігурацією для WT32-ETH01.

Основні бібліотеки:
- Adafruit PN532 та Adafruit BusIO — зчитувач NFC
- ESPAsyncWebServer та AsyncTCP — асинхронний вебсервер і WebSocket
- ArduinoJson — обмін даними у форматі JSON
- PubSubClient — MQTT

## Як прошити плату

### Підключення

- ESP32 програмний порт (USB-UART) підключається до UART плати WT32-ETH01
- Підтвердіть, який COM-порт реально використовується в Device Manager
- Для прошивки в PlatformIO зазвичай використовується порт, який відповідає `upload_port = COMx`

### Команди PlatformIO у терміналі Windows

Відкрийте термінал VS Code (**Terminal → New Terminal**) і перейдіть у папку
проєкту. Підключіть плату через USB-UART та дочекайтеся завершення кожної
команди перед запуском наступної:

```powershell
cd "$env:USERPROFILE\Documents\PlatformIO\Projects\wt32-eth01"
.\.venv\Scripts\platformio.exe run --target upload
.\.venv\Scripts\platformio.exe run --target uploadfs
```

Спочатку виконайте `upload`, потім — `uploadfs`: друга команда завантажує
вебсторінки в LittleFS. Не стирайте Flash. Розділ карток відокремлений, тому
`uploadfs` не повинен видаляти збережені картки.

### Якщо потрібна перевірка серійного порту

```bash
python -m platformio device list
```

### Підсумок підключень

- PN532 SDA -> GPIO 33
- PN532 SCL -> GPIO 32
- PN532 IRQ -> GPIO 4
- PN532 RESET -> GPIO 5
- RELAY_1 -> GPIO 14
- RELAY_2 -> GPIO 15
- BUTTON_ADD -> GPIO 39
- Ethernet PHY LAN8720 -> як у конфігурації ETH

## Примітка

Якщо сторінка відкрита через роутер, використовуйте DHCP-адресу WT32-ETH01,
а не `192.168.4.1` (це адреса резервної точки доступу). Перевірте фактичні
пін-назначення вашої плати перед підключенням периферії.
